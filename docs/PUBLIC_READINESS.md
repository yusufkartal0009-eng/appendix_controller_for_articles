# Publication readiness audit (2026-10-22)

This is an audit, not a decision. The repository is private. Whether and when to make it public is the owner's decision
(`docs/PENDING.md`, D1). The audit looked for things that would become visible to everyone: secrets, personal data, local
paths, large or copyrighted files, and text meant only for the owner. Nothing was changed in the history, in the settings
of the account, or in the visibility of the repository. No secret value is written here.

## What was searched

| Where | How | Size |
|---|---|---|
| Tracked files of `main` | `git grep` for the patterns below | 1,045 files |
| The whole history | `git log --all -G<pattern>` for each pattern; the list of author and committer identities | 423 commits |
| Issue and pull request text | `gh issue list` and `gh pr list` (title and body), patterns below | 220 issues, 210 pull requests |
| Files that exist in history but not in `main` | the one `.docx` found in history was extracted and its text and metadata read | 2 versions |

Patterns: API keys and tokens (`sk-`, `ghp_`, `github_pat_`, `AKIA`, `xox*-`, PEM private keys), assignments of a literal
to `api_key`, `secret`, `password` or `token`, e-mail addresses, the local path of the working machine, host names and IP
addresses, file names such as `.env`, `*.pem`, `*.key`, `*.db`, `credentials`.

## Results

### No secret found (with limits)
- **Tracked files:** no match for any key, token or private-key pattern, and no literal assigned to `api_key`, `secret`,
  `password` or `token`.
- **History:** 0 commits match any of the six key and token patterns.
- **File names:** no `.env`, key, certificate, database or backup file is tracked now, and none ever was (`*.db` and `.env` are in
  `.gitignore`).
- **Limits of this search:** it finds only the listed patterns. A password or token in another form would not be found. Git cannot
  search inside the history's `.docx` (see below), so that file was read separately. The comments under issues and pull requests
  were not searched, only their titles and bodies.

### Personal data
- **E-mail address of the owner.** The author identity (the account name with the owner's personal e-mail address; the address is not repeated here) is stored in **228 commits**
  (211 as author with GitHub as committer, 17 as author and committer). 186 other commits use the GitHub noreply address, and
  4 use the noreply address of a collaborator. Once the repository is public, these addresses are visible in the commit metadata
  to everyone. The address also stands in one line of `docs/PROGRESS.md` (line 730, a note about the Git identity). Removing it from a
  file does not remove it from the history. **Decision for the owner:** accept it, or publish a new repository from a snapshot
  (this loses the history), or rewrite the history (destructive; every commit hash changes and the links in issues and pull
  requests no longer match). No history was rewritten.
- **A placeholder identity** `Yusuf <yusuf@example.com>` appears in 5 commits. Harmless.
- **Names.** The owner's full name stands in the draft `docs/repro_radar_introduction.docx` of the history (see below) and
  collaborators are named in the commit metadata. `LICENSE` names "Repro Radar Contributors". No telephone numbers were found.
- **The GitHub account name** (`yusufkartal0009-eng`) is in the clone address in the README and in about 30 tracked files; it is the
  address of the repository itself.

### Local paths
- **Tracked files:** no occurrence of the local path of the machine (`C:\Users\USER` or its forward-slash forms) in the current files.
  Records of earlier runs had it replaced by `<REPO>` and `<HOME>`.
- **History:** 6 commits (2026-10-04 to 2026-10-13: the Pilot 2 and Pilot 3 records, a sandbox fix, a note on the blind packet) added
  or removed lines with that path. The account name in it is a generic one (`USER`), so the risk is low.
- **Issues and pull requests:** the path stands in the bodies of 1 issue (#246) and 4 pull requests (#187, #199, #203, #247).
- **IP addresses and host names:** the only matches are version numbers of packages (for example `10.3.2.106`) in install logs. No host
  name of the machine was found.

### Files
- **Size:** the packed history is 3.06 MiB. No tracked file is larger than 2 MB.
- **Copyrighted papers:** the PDFs of the papers are not tracked (`data/pdfs/` is ignored, `.gitignore` line 93), and neither is
  the cached full text (`data/pdf_text_cache/`). Two tracked PDFs are reports generated by the tool (`docs/evidence/d4/`). The
  claim files hold short verbatim quotes from the papers (a table row each) with the page, as the quote guard requires; their total
  size was not measured. A reviewer for copyright may want to look at them.
- **Screenshots:** 12 images in `docs/evidence/` (dashboard pages, badges, report pages). The one opened for this audit shows only
  papers and statuses, no personal data; the other 11 were not opened.
- **A `.docx` in the history:** `docs/repro_radar_introduction.docx` was added on 2026-09-18 and removed on 2026-10-01. Its text and
  properties were read: no e-mail address, no telephone number, no key. The text contains the owner's name. The author property
  is `python-docx`.

### Text meant for the owner or the assistants
- `AGENTS.md` and `CLAUDE.md` (instructions for coding assistants) are tracked. They describe the working rules of the project (`docs/PLAN_2026-10-01.md`, item Y2, names an `AGENTS.md` rule about AI attribution that is
  an open question with the mentors). They were not re-read in full for this audit. They are visible to everyone once the repository is public.
- `docs/PLAN_2026-10-01.md` and the reports name the questions for the mentors (for example item Y2 about issue `#165`, which does
  not exist in this repository). They contain no personal data but expose open internal questions.
- `docs/PROGRESS.md` is a long working log. It holds merged entries in an order that is not always chronological
  (`docs/PENDING.md`, section 5).

### Licence and attribution
- `LICENSE` is MIT, "Copyright (c) 2026 Repro Radar Contributors". There is no `CITATION.cff`.
- The corpus holds only repositories with open licences that match the declared one (`scripts/verify_corpus.py`).

### Other things that become public
- **All issues, pull requests and their comments** become visible. Some comments were written by an assistant in the owner's name,
  with the owner's approval; this is part of the record. They were not re-read for this audit.
- The 12 papers' run logs (`data/pilot*_runs`, `data/demo_set/`) are tracked; they print the output of third-party programs.
