## 0. Decisions that change with this plan → #168

Yusuf made the decisions below. The agent will write them to `docs/DECISIONS.md` in English, with their reasons.

1. **No API key will be used (for now).** Claim extraction will be done by the Claude Code agent ("agent-assisted
   extraction"): it will read the paper text and record every claim as JSON according to the W1 schema, with its
   verbatim quote and page number. The API code from PR #156 will not be deleted; if a key becomes available later,
   it will be used with the same schema.
2. **The "temperature 0" requirement is dropped.** A simpler consistency rule replaces it:
   > When the same claim is found in two separate extractions, **the numeric value after W1 normalization must be
   > the same** (e.g. `96.99 %` → `0.9699`). The quote text, the description, or the field names may differ; all that
   > matters is that the numbers agree. Every value that does not agree goes to Yusuf for approval in W7.
3. **No server or website.** Everything will run locally on Yusuf's computer (the dashboard too, on `localhost`).
   Paper runs will be done locally once Docker is installed on Yusuf's computer; GitHub Actions will stay only for CI.
4. **Papers that cannot be fixed may be replaced with new ones (#166).** But every replacement is recorded with its
   reason, and the first pilot result (0 / 6) stays on record. Choosing only papers that "work" would raise the
   success rate artificially.

## 3. Work loop for every step (→ #115)

1. Write an estimated time and a 3-point plan on the issue.
2. Open a branch, implement.
3. Run the tests, show the output.
4. Update `docs/PROGRESS.md` with the real date and time.
5. Open the PR (what/why, how tested, what I did NOT verify, AI use), read the diff, write a self-review comment.
6. If CI is green, merge. Write a "done / left" comment on the issue.

**Rules that do not change:** no "verified" without evidence; simulated data is not presented as a real result; API
keys and personal data are never committed; no force-push, no direct commit to `main`.
