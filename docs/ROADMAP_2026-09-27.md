## 0. Why this order → #121

The corpus is now real (6 papers, all with a runnable repository and script). But only 2 of the 16 claim values turned out as written in the paper. The other 14 were either not found or wrong.

There is a trap here: saying "first fix the 14 values by hand, then run the pilot" looks tempting, but **fixing by hand could produce the same error a third time.** In the first round the 18 papers were invented; in the second round they were cut to 8, but 6 of them were still broken. Instead of writing a list by hand a third time and saying "this time it is right", a system should be built that **extracts the claim values by machine and verifies them with a quote** (W1-W7 in the TODO). This is both more reliable and an already planned part of the project.

Good news: the pilot run (P1-P7) does not have to wait for this fix. What the pilot really measures is "does the install succeed, does the script run without errors" (Tier 1), not whether the claim value is correct. So **the pilot first, claim extraction afterwards** can work. The order below follows this.

**The order is binding:** Section 1 is small and should be done right away. Section 2 (pilot) and Section 3 (claim extraction) are not prerequisites of each other, but Section 4 (connecting the CLI to reality) and Section 5 (report) must not be written before all three are done.

## 3. Claim extraction (W1-W7) - fix the 14 wrong values by machine → #9

### What happened / why this way

`CORPUS_VERIFICATION.md` already lists, row by row, which 14 values are wrong. This is a very good starting point. What is to be done now is not to fix them one by one by hand, but **to build a system in which they can never be entered wrongly again.**

Note: TabNet (the old regression example) is no longer in the corpus, so the test cases will be taken from real `SUSPECT` findings: `paper_005` citing a dataset "EP3602" that does not exist, and `paper_008` citing a "HIGGS" dataset that never occurs in the paper. These are real regression cases in which the extraction engine must be able to say "not in the paper".

### To do

1. **W1 - Claim schema** (`docs/CLAIM_SCHEMA.md`): `metric_name`, `value_as_printed`, `value_normalized`, `unit`, `dataset`, `model_variant`, `split`, `higher_is_better`, `table_or_figure`, `page`, `source_quote`, `confidence`. Normalization example: `96.99 %` → `0.9699`. → #129
2. **W2 - PDF text extractor.** `pypdf` has so far only been used by hand (stated in `CORPUS_VERIFICATION.md`) and is not in `requirements.txt`. Add it and make a module: text page by page, page numbers kept, cached by the paper's hash. Tables can collapse into a single line (this was already seen in `CORPUS_VERIFICATION.md`'s own PDF extraction note); document this limitation. → #130
3. **W3 - Extraction prompt + structured output.** Temperature 0, JSON-schema output, it **must quote** the source, and it must say "not found" instead of guessing. Choose a single model provider and add the reason to `docs/DECISIONS.md` (the file already exists, as an entry like D-002). The API key comes only from an environment variable, is never committed, and responses are cached. → #131
4. **W4 - Hallucination guard.** Every `value_as_printed` and `source_quote` must occur **verbatim** in the page text; if it does not, the claim stays `UNVERIFIED` and is not used in scoring. → #132
5. **W5 - Gold set + evaluation.** Extract the claims of 3 papers by hand (`tests/data/gold_claims/*.json`), from the paper text, not from the LLM extraction. Measure precision/recall. Mandatory regression cases: → #133
   - For `paper_005`, a query for "EP3602" must result in "not found" and must not match EP300 by mistake.
   - For `paper_008`, a query for "HIGGS" must result in "not found".
   - A value the paper really reports (example: `paper_003`'s already verified `ft_transformer_rmse: 0.459`) must come out correctly.
6. **W6 - Store it with its source.** SQLite: paper id, page, table, quote, extractor version, `verified_by` (`auto-quote-match` / `human`). → #10
7. **W7 - Human confirmation step.** The CLI lists the extracted claims and asks accept/reject for each one. Only accepted claims enter scoring. → #134
8. **Closing:** update the `expected_claims` field in `data/seed_papers.json` with the values that went through this process and were accepted. Remove the "UNVERIFIED" and "SUSPECT" labels in `CORPUS_VERIFICATION.md` for the corrected records. → #135

### Counts as done when

- Claims have been extracted for at least 3 papers, verified with a quote, and compared with the gold set; the precision/recall numbers are in the PR.
- The two regression cases (EP3602, HIGGS) give "not found", not an invented match.
- The values in `seed_papers.json` are now real and consistent with `CORPUS_VERIFICATION.md`.
